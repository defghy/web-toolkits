# 互联网技术知识地图：技术实现方案

状态：待审阅；已建立普通 Web 项目骨架，知识地图尚未开发。  
日期：2026-11-04。  
项目：`packages/wtool-know-map`。

## 1. 本轮目标

页面只有一张可交互的知识地图，采用类似 webpack 包分析的嵌套矩形效果：大矩形表示职责或领域，点击后在矩形内部显示子分类，再继续展开到库、框架、产品与工具。

采用**矩形树图（Treemap）**呈现分类包含关系，减少树形连线图的空白与横向扩张。浏览过程为：互联网技术 → 职责领域 → 功能/方向 → 实现方案 → 具体技术。分类允许任意深度，不固定为职责、功能、实现三层。

首版聚焦单图、逐级展开/收起、局部聚焦、路径搜索与简短技术说明。调用、依赖等保留为关系数据，在技术说明中展示相关入口；首版不再增加分栏、独立关系图或链路视图。

知识数据以主要功能范围完整为目标，先录入代表实现，后续持续补充，不以穷举全部互联网技术为验收要求。

## 3. 图形方案与技术选型

### 3.1 为什么选 Treemap

Treemap 用子矩形嵌套表达父子包含关系，适合“领域 → 子领域 → 技术”的多层分类，也符合用户提出的矩形内部逐渐出现更多矩形的交互。

它能提高空间利用率，但屏幕仍有可读性限制。首版通过“按需展开 + 放大聚焦 + 层级返回”浏览大量知识，不把几千个标签同时压进一个视口。

| 方案                   | 适配情况                                                | 结论                                               |
| ---------------------- | ------------------------------------------------------- | -------------------------------------------------- |
| G6 Rect Combo          | 支持节点与子 Combo 嵌套、折叠，适合同时展示分组与关系边 | 可用于未来关系探索，但矩形区域的铺满布局需额外处理 |
| G2 Treemap             | 提供矩形树图与下钻交互                                  | 合适备选；若采用标准点击下钻，可直接使用           |
| D3 hierarchy + Vue SVG | D3 计算矩形坐标，Vue 控制点击、局部展开、文字和说明     | 首版采用，方便精确控制“在原矩形内展开”的行为       |
| 力导向、普通树图       | 更侧重关系或层级连线，需要较多空间                      | 当前交互不采用                                     |

上述能力参考 [G6 Combo 文档](https://g6.antv.antgroup.com/en/manual/element/combo/overview/)、[G2 Treemap 文档](https://g2.antv.vision/zh/charts/treemap/) 和 [D3 Treemap 文档](https://d3js.org/d3-hierarchy/treemap)。技术选型基于本项目的局部展开交互，不要求使用 G6。

### 3.2 技术栈

- Vue 3 + TypeScript + Vite，沿用现有项目骨架。
- `d3-hierarchy` 只负责 Treemap 布局，配套类型声明；不引入整个 D3。
- Vue SVG 负责矩形、文字、层级边框与交互；Vue DOM 负责工具栏、搜索候选和浮层。
- Composition API 管理状态，CSS 变量管理配色；首版不引入完整 UI 框架与状态管理库。
- vue-tsc、数据校验脚本和 Vitest 验证类型、数据不变量、路径与布局规则。

后续安装时选择与现有工作区兼容的版本并更新锁文件，优先对齐仓库的 Node 22 环境。首版只有一个图引擎实现，不同时引入 G6、G2 与 D3。

## 5. 单图页面与点击规则

### 5.1 页面结构

```text
┌──────────────────────────────────────────────────────────┐
│ 搜索：技术或功能   返回上级   返回全景   重置展开           │
│ 路径：互联网技术 → 前端与用户交互 → 专业能力               │
├──────────────────────────────────────────────────────────┤
│ ┌─────────────────────────┐ ┌──────────────────────────┐ │
│ │ GIS / 地理信息          │ │ 3D 渲染                  │ │
│ │ ┌─────────┬───────────┐ │ │                          │ │
│ │ │ 地图展示│ 地理计算  │ │ │ 点击后内部显示子矩形     │ │
│ │ ├─────────┴───────────┤ │ │                          │ │
│ │ │ 三维地理场景       │ │ └──────────────────────────┘ │
│ │ └────────────────────┘ │ ┌──────────────────────────┐ │
│ └─────────────────────────┘ │ Canvas / 2D 绘制         │ │
│ 其他方向矩形……              └──────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

初次打开显示互联网技术顶层职责矩形。每个分类矩形包含名称、子项数量及展开标记；技术矩形显示名称和类型。首屏不自动展开全部后代，也不设置常驻详情栏。

### 5.2 展开与收起

1. 点击有子项的矩形主体：在该矩形内部显示直接子项，父区域保留标题和边框，位置与外部兄弟矩形不变。
2. 继续点击子项：在其内部再展开一层。可同时展开多个不同分支，展开不等于替换整个地图。
3. 已展开父区域的标题处显示收起按钮，点击后隐藏其后代。对子矩形的操作不冒泡到父区域，避免一击展开多层或意外收起。
4. 子项太多、空间不足时，父矩形显示“聚焦查看 N 项”，点击后将该分支放大为当前地图范围，再继续浏览；不强行绘制不可点击的小块。
5. 每个分类标题提供显式“聚焦”按钮。顶部面包屑、返回上级、返回全景用于退出聚焦，恢复上一级地图及其展开状态。
6. 叶子技术没有子项时，点击显示简短信息浮层，包含职责、类型、语言、官方资料及相关技术入口；空分类显示“待补充”，不伪造子项。

点击展开与点击聚焦分别使用主体和明确按钮，不用双击作为必需操作。所有非叶子分类支持展开，叶子实体以说明响应点击。

### 5.3 面积、标签与可读性

- 本地图没有包体积、流行度或重要性指标，面积仅用于排版，界面提示“矩形面积不代表技术重要性”。
- 各父节点的直接子项默认使用相等布局权重，在保留标题与间距后分配区域；不按技术数量改变所有祖先面积。
- 每个父区域内独立布局，展开子项只改变该父区域内部，不推动其他区域。
- 名称空间不足时截断，悬停显示完整名称；面积再小则保留父级与“聚焦查看”入口，避免大量无文字小块。
- 同一顶层职责使用同色系，不同深度用边框与明暗区分。类别与技术同时有类型文字，不只依赖颜色。
- 窄屏使用同一张地图和聚焦规则，触屏点击查看说明；不依赖鼠标悬停才能阅读内容。

## 6. 搜索：路径展示与地图定位

搜索在整份知识数据中进行，与当前聚焦范围无关。输入 Vue 后，候选展示：

```text
前端 → Web 端 → Vue
UI 库 / 框架 · 渐进式界面框架
```

底层完整路径可能为“互联网技术 → 前端与用户交互 → 平台与应用形态 → Web 端 → UI 库 / 框架 → Vue”。根节点及仅用于组织维度的通用分组可从候选主路径中省略，通过路径别名将“前端与用户交互”显示为“前端”；完整路径在辅助说明与定位后的面包屑中保留。

路径基于当前分类数据生成。核心功能和区分入口的分类不得省略，例如“数据与存储 → 数据库 → 非关系型 → 键值 → Redis”。同一实体有多个入口时分别展示候选，不因共享实体而合并不同路径。

选中搜索结果后：

1. 通过展示条目 ID 找到完整祖先路径。
2. 默认聚焦到目标所属的最近可读分类，展开必要祖先及目标，确保目标矩形有可读面积；此前范围可通过返回操作恢复。
3. 高亮目标矩形并显示名称与技术说明；面包屑保留从根开始的完整路径。
4. 连续选择时只完成最后一次定位，不被旧动画覆盖。

候选按名称/别名精确匹配、前缀、包含匹配排序，同级按路径稳定排序；支持 `k8s`、`rn`、中文功能名称。方向键切换、Enter 确认、Escape 关闭，首版展示前 20 条并提示总数。

## 7. 数据与布局实现

### 7.1 唯一实体与展示树

```ts
interface TechEntity {
  id: string
  name: string
  aliases: string[]
  kind: string // 语言、协议、库、框架、产品、运行环境等
  summary: string
  sources: { title: string; url: string; checkedAt: string }[]
}

interface MapEntry {
  id: string
  parentId?: string // 除根外必须有父节点
  label: string
  kind: 'root' | 'domain' | 'dimension' | 'function' | 'approach' | 'technology'
  entityId?: string // technology 必填
  classificationBasis?: string
  searchLabel?: string // 路径短名称，例如“前端”
  compactInSearchPath?: boolean // 仅通用分组可省略
  order: number
}

interface TechRelation {
  id: string
  sourceId: string // 技术实体 ID
  targetId: string
  type: 'calls' | 'runs-on' | 'managed-by' | 'uses-language' | 'integrates-with'
  description: string
  context: string
}
```

一份展示树对应一张地图，技术实体可由树中多个条目引用。数据树保持唯一父节点和无环；实体关系单独保存，允许跨树分支和循环，不参与 Treemap 的嵌套布局。

同一实体的不同入口具有独立的展开与选择 ID，介绍和资料共享。Redis 可以同时位于数据库与缓存，CesiumJS 可以同时关联 GIS 与 3D。

预建索引：`entryById`、`childrenByParentId`、`entityById`、`entryIdsByEntityId`、`ancestorIdsByEntryId`、完整路径与搜索路径。增补分类无需改变图组件或固定层级字段。

### 7.2 布局流程

1. 根据 `focusEntryId` 确定当前范围，默认是全局根节点。
2. 将当前父区域的直接子项构成一层临时 D3 hierarchy，子项权重均为 1；使用 `treemapSquarify` 计算坐标，按 `order + id` 稳定排序。
3. 为父矩形保留标题高度和内外间距；仅对子项已展开的分类递归执行上述布局。
4. 子区域坐标转换到地图统一坐标系，Vue SVG 按 `entryId` 绘制。标题、技术浮层与可点击区域分层处理，文本不跨父矩形溢出。
5. 如果子项不能满足可读阈值，停止该区域更深绘制，显示聚焦入口。初始参考阈值为子块宽 96px、高 48px，实际按标签长度和视口调整。
6. 聚焦相当于更换当前根并重新布局，原始数据不变；顶部完整路径用于返回和说明当前位置。

D3 只输出坐标，Vue 统一控制 SVG 和状态，不让 D3 与 Vue 同时修改 DOM。每个父区域只布局一层，避免展开后因后代权重变化导致全景矩形不断换位。

### 7.3 状态与资源管理

状态包含 `focusEntryId`、`expandedEntryIds`、`selectedEntryId`、搜索词和候选索引、返回历史。浮层属于临时状态，展开集合按展示条目 ID 保存。

URL hash 保存聚焦与选中条目，支持分享；localStorage 保存展开状态与数据版本。URL 指定项优先于历史，失效 ID 回退到最近有效祖先或根节点。返回上级按分类父节点，返回按钮按访问历史；两者文字明确区分。

ResizeObserver 在尺寸改变时重新计算当前范围。快速点击、搜索、聚焦采用递增操作序号取消旧定位与动画；卸载清理观察器与事件。支持减少动态效果偏好。

初始仅展示约 8 个顶层区域，常见交互控制在约 200 个可见矩形，超过阈值引导聚焦。首版不增加 Worker、远程懒加载或虚拟列表。SVG 适用于此可见规模，后续实测有压力再换 Canvas，保留数据和布局接口。

4. 补齐操作系统、后端、缓存、容器、CI/CD 等主要领域数据与官方资料。
5. 验证可读性、键盘/触屏、刷新恢复、构建和性能，交付本地可审阅页面。

## 9. 验收标准

| 范围         | 可检查的结果                                                     |
| ------------ | ---------------------------------------------------------------- |
| 单图         | 页面只有一张嵌套矩形地图，没有常驻左右分栏或独立第二张图         |
| 原位展开     | 点击分类后在其矩形内部出现子项，外部兄弟区域位置保持不变         |
| 任意深度     | 能继续展开多级专业方向与技术生态，无固定三级限制                 |
| 前端专业方向 | GIS、3D、Canvas 均有入口，平台与专业能力分类维度清楚             |
| 数据库       | MySQL 位于关系型入口，文件型与关系型使用不同分类维度             |
| 共享实体     | 同一技术的多路径入口独立定位，资料共享                           |
| 聚焦返回     | 密集小区域可放大聚焦，通过面包屑回到任意祖先并保留展开状态       |
| 路径搜索     | Vue 候选展示“前端 → Web 端 → Vue”，选择后目标可见且高亮          |
| 详情与关系   | 叶子点击显示简短说明，跨领域关系通过相关入口浏览，不误当父子包含 |
| 稳健性       | 快速操作不会定位到旧目标，失效 URL 与禁用存储不会白屏            |
| 数据与工程   | ID、引用、路径、无环校验通过；类型检查、核心测试和生产构建通过   |

核心测试验证分类树无环、实体多入口、路径生成、布局不重叠且包含于父矩形、原位展开不改变外部区域、聚焦/返回状态恢复与搜索定位。交互可用性以浏览器操作验证，不增加镜像实现的样式快照测试。

性能目标：约 200 个可见矩形下，点击到稳定绘制 P95 小于 300ms；本地约千条展示入口的搜索响应小于 100ms。实施时记录机器、浏览器、数据规模和至少 20 次操作样本，这些是待测目标。
